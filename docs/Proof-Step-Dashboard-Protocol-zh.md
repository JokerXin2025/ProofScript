# 普通脚本步骤仪表盘：第一阶段协议

本协议确定普通 script 步骤的配置、录制数据与页面交互边界，供后续 Lean 导出、PS4HTML 渲染及前端实现共同使用。

## 适用范围

- 仅对有对应 recorder 步骤的**普通 script** 启用点击展开。`unknown`、`calc`、`infer`、`introducer` 等特殊步骤不启用；strategy 和元数据暂不支持。特殊 renderer 即使产生 `proof-step` 也不因此自动获得仪表盘。
- 所有 script 的 `script_info` 均允许配置 `board`，包括暂时不支持仪表盘的 strategy 和元数据；配置存在不意味着页面必须显示。
- 步骤原内容始终位于面板顶部。展开后，上部左右栏分别标为「原状态」和「新状态」，各栏先显示上下文，再显示目标；下部按 `board` 展示录制字段。`board` 为空时不渲染下部。

## `script_info.board`

Lean 字段类型为 `List (String × String)`，默认 `[]`：

```lean
script_info «example» {
  board := [("使用的假设", "h"), ("提供的表达式", "value")]
}
```

元组第一项是展示名 `name`，第二项是 recorder 字段名 `value`。导出的 Info JSON 使用**有序对象数组**：

```json
"board": [
  {"name": "使用的假设", "value": "h"},
  {"name": "提供的表达式", "value": "value"}
]
```

- 保留列表顺序，允许重复展示名，也允许多个展示名引用同一个录制字段。
- 多次配置 `board` 时后一次赋值**整体替换**前一次；`[]` 可清空。
- `value` 是录制对象上的**字面键名**，例如 `"foo.bar"` 只查找 `step["foo.bar"]`，不沿对象路径查找。
- 未录制的配置字段显示该展示名及「未记录」，不使整页渲染失败。显式 `null` 则显示 `—`；二者不同。
- 值中的表达式引用按现有表达式根清单及解析渲染器处理，字符串按文本转义；列表、对象等使用结构化展示。不得将未经声明的普通对象推断为表达式。
- Lean 端应为此字段提供专用 codec：Lean 使用元组列表，JSON 为 `{name, value}` 数组。Python 端对数组元素、字符串类型及字段键名作协议校验，不将数组压成 JSON 对象。

## 状态字段

普通步骤可包含以下保留字段：

| 字段 | 含义 | 数据 |
| --- | --- | --- |
| `$context_before` | 原状态的上下文 | JSON object：假设名称到表达式引用的映射 |
| `$context_after` | 新状态的上下文 | 同上 |
| `$goal_before` | 原状态的目标 | 表达式引用或 `null` |
| `$goal_after` | 新状态的目标 | 表达式引用或 `null` |

Lean 的 `record_context` 遍历选定目标的可见局部上下文，将局部声明名称映射到其类型表达式引用；自动 recorder 与 `record_goal` 同步记录，手写 recorder 可指定键名及 `(goal := 标签)`。没有剩余目标时记录 `{}`。页面仍支持旧录制数据或手写 recorder 中字段缺失的情况：缺失时隐藏对应栏的上下文区域；存在但为空对象表示已采集到空上下文。只录制单侧上下文时，不把未录制的一侧当成空对象，也不推断所有假设均新增或删除。假设名称按文本转义，值作为表达式引用交给现有表达式解析和高亮机制。表达式引用必须满足当前证明文档的 `expressionRoots` 声明要求。

目标字段缺失或为 `null` 时，该侧显示「✓目标已完成」，其中 `✓` 替代 `⊢`；存在表达式引用时展示 `⊢` 和解析后的目标。普通 script 不产生多目标，此处只处理单一目标。

## 状态对比与交互

- 显示全部上下文，包括未变化的假设；同名假设按引用所指的表达式内容比较，变化时原状态行显示红色 `－`、新状态行显示绿色 `＋`，与内容之间保留间距。同名假设在前后栏占同一行，单侧不存在时另一栏留白；目标固定在对齐的上下文行之后。目标始终只显示 `⊢` 或绿色 `codicon-check`，不添加增删符号；差异不使用行背景色。使用 PS4HTML 现有的表达式高亮交互。
- 展开入口是步骤头部，点击再次收起；仪表盘正文的点击不收起，内部已有公式、链接等交互优先。多个步骤可以同时展开。提供键盘操作及 `aria-expanded` 状态。
- 展开区域填满当前证明内容宽度，不越过所属分支；窄屏继续保留左右对应栏，必要时允许内容换行。仪表盘不显示分界线；步骤 hover 和展开时使用几乎不可见的淡蓝背景（包括没有仪表盘的步骤）。动画沿垂直方向平滑展开、收起，适应内容高度变化和减少动态效果设置。头部不触发浏览器选中文字，仪表盘正文仍可复制。
- 初始收起，不跨刷新保存状态。同一定理的不同语言面板中，切换对应步骤时同步展开状态；切换语言时不会把已展开的步骤重置。

## 后续构建检查点

1. Lean：在 `ScriptInfo` 中增加字段及专用 codec，检查配置覆盖语义、Info schema 和导出数据。
2. Python：在模块规则传递和 `validate_rules` 中接入 `board`；校验状态字段与表达式根，按字面键读取 board 值；只为适用的普通步骤生成仪表盘。
3. 页面：为步骤渲染添加面板结构、状态比较、动画与响应式样式，同时保留表达式解析、尺寸适配及原有点击交互。
4. 验证：重复展示名与顺序、点号键名、缺失/null/空对象、单侧上下文、完成目标、表达式引用、高亮、嵌套分支、语言切换及特殊步骤禁用。

Lean 自动 recorder 已产生 `$context_before` / `$context_after`；strategy 的特殊展示仍不启用仪表盘。
