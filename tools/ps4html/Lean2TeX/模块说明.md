# Lean2TeX 模块说明

Lean2TeX 接收 ProofScript 导出的 ExprJSON，根据证明模块导入的 Lean 配置生成 DisplayTree 和 TeX。配置声明在 Lean 文件中；渲染器不读取 TOML。

## 配置链路

1. `ProofScript/Lean2TeX/Command.lean` 定义 `def_info`、`var_info`、`phrase_info`；`Registry.lean` 将显式字段及来源保存到持久化环境扩展。
2. Lean 在 `.ProofScript/lean2tex/events/<模块>.json` 导出本模块与导入模块的配置事件（包括空模块），已有 `.ProofScript/rendering/modules/` 提供导入图。
3. `configuration.py` 的 `ConfigurationIndex(export_root).effective(proof_module)` 按实际导入关系和源顺序合并，检测独立导入的字段冲突、无效布局和 alias 环。模块自身新声明的配置仅供导入它的模块使用。
4. `Expr2TeX.from_config(config)` 为每个证明/语言面板创建独立的变量分配器和诊断状态。PS4HTML 在发布前检查配置，在渲染时使用同一个导出根；缓存重渲染只消费 `.PS4HTML/inputs/` 中的 `.ProofScript` 快照。

`def_info` 目标和 alias 目标必须是已经声明的 Lean 常量。`alias`、`unwrap` 是优先解释的模式；只有 `calc_symbol` 而无 styles 时，Python 为二元关系生成优先级 50、无结合方向的中缀样式。`styles` 以整个有序数组覆盖，`phrase_info.template` 按语言更新，`var_info.names` 保存池顺序。省略字段沿用已有配置，`none` 显式清除。

## Python 文件职责

| 文件 | 职责 |
| --- | --- |
| `configuration.py` | 模块 manifest/事件读取、合并、冲突与数据验证、构造有效配置 |
| `macros.py` | `MacroRegistry`、模板选择器与宏布局验证 |
| `semantic.py` | ExprJSON 转换为 DisplayTree，解析应用参数、fvar、binder 与 bvar |
| `renderer.py` | 布局、优先级/括号、文本与公式模式、TeX/KaTeX 语义引用 |
| `variable.py` | `var_info` 命名池、变量名称分配及 fvar 缓存 |
| `core.py` | `Expr2TeX` 公共接口及按导出目录/模块加载 |

`#N` 指筛选后的语义子节点，`@N` / `@@N` 在 `binders := [(N, count)]` 指定的 lambda 中选择 binder 和后续部分。某个 style 依赖 binder 时，需保留不使用 `@` 的后备样式；同名 style 依声明顺序选择。`unwrap` 则按包括隐式参数在内的原始应用参数下标选取。

变量高亮身份不依据显示名称：fvar 使用 `fvarId`，binder/bvar 使用同一次转换的 `bindId` / `bindRef`。`renderer.py` 输出 `\htmlData`，浏览器只在最近的 `.theorem-proof` 中联动同组引用。

配置示例与公开 API 见 [README.md](README.md)；协议和迁移背景见仓库根目录的 `docs/Lean2TeX-Lean-Configuration-Phase-1-zh.md`。
